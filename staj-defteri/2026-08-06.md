## Öğrendiklerim

**1. Klasik ReAct ≠ modern tool-use loop.** Klasik ReAct bir prompt tekniği (metin `Thought:/Action:` parse edilir). Native tool-calling structured; thinking model varsa reasoning de native. Bizim ajan structured tool-calling döngüsü — model thinking olsun olmasın klasik ReAct değil. Ayrım: reason (model içsel, biz kör) → act (structured tool_calls) → observe (compaction'dan geçmiş). Katkımız observe ayağında.

**2. Mock deterministiklik gerçek kusurları maskeler.** Koruma-penceresi turn-hatası ve benefit-guard eksiği ancak canlı gemma + gerçek tool bağlanınca çıktı. Deterministik test tekrarlanabilir ama gerçek-model varyansını (aynı turda çok tool, tekrar çağırma) göstermiyor. İkisi de lazım.

**3. Framework-agnostik katman altın değerinde.** Stratejileri mesaj değil kendi ToolResult modelimiz üzerine kurmam, aynı 13 stratejinin hem gerçek 119 tool'a hem LangGraph'a **hiç değişmeden** takılmasını sağladı. Adaptör ince kaldı (tools_product ~90 satır, LangGraph hook ~30 satır).

**4. sys.path'e dizin eklemek gölgeleme riski.** İki dizinde de `agent.py`/`chat.py` olunca `sys.path.insert(0, ...)` yanlış modülü çözüyordu. Modül sadece stdlib'e bağlıysa `importlib.util.spec_from_file_location` ile dosyadan izole yükle — path'e hiç dokunma.

**5. Dedup/staleness güvenli ama fayda freni yine de şart.** Dedup en tazeyi tutup fazlalığı atar (güvenli), ama çıktı zaten küçükse not ondan büyük olabilir → negatif kazanç. Güvenli işlem ≠ her zaman faydalı işlem.

**Sorun 1 — Canlı ajanda %0 tasarruf.** Koruma penceresi turn-tabanlıydı; gerçek ajanda tek turda çok tool var → hepsi korunuyordu. Konum-tabanlı (son N tool) yaptım.

**Ders:** aynı-adlı modüller olan projelerde asla `sys.path.insert(0)` yapma; izole yükle.

**Sorun 3 — Negatif tasarruf (docx staleness).** Küçük çıktı, büyük not. Dedup/staleness'e benefit-guard ekledim.
**Bir dahakine:** her compaction adımına "not < ham mı" freni koy, sadece kayıplı olanlara değil.

**Sorun 4 — LangGraph varsayılanı sistem python'da çalışmaz.** langgraph venv'de; `python3 chat.py` (sistem) onu import edemez. `engines.make_live_agent`'a try/except yedeği koydum → langgraph yoksa sessizce manuel loop'a düşer (hiç kırılmaz). Varsayılan için `../.venv/bin/python` ile çalıştır.
