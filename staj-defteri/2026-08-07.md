### 2. İki harness anatomisi — biri kapalı kaynak, biri açık

**Ne:** Claude Code ve Hermes-Agent için "kullanıcı girdisinden nihai yanıta kadar kontrol döngüsünün her adımı" düzeyinde iki ayrı belge.

**Nasıl — ve aradaki fark:**

**Claude Code (kaynak KAPALI):** Belgeye açık bir dürüstlük notuyla başladım — `anthropics/claude-code` reposu **çekirdek kaynak kodu içermiyor**, orası bir dağıtım + issue-tracker hub'ı; CLI minify edilmiş bundle olarak dağıtılıyor. Harness'ı üç doğrulanabilir kaynaktan yeniden inşa ettim: (1) resmî docs (hooks lifecycle, sub-agents, memory, permissions, MCP sayfaları birebir), (2) **Claude Agent SDK** — Claude Code'un açık kütüphane hâli, aynı harness/aynı loop, (3) çalışma-zamanı davranışı (gözlemlenebilir system-reminder'lar, tool sözleşmeleri, permission modları). Yani "satır satır kod" değil, **davranışsal + docs-doğrulanmış anatomi**; emin olmadığım yerleri işaretledim.

**Hermes (kaynak AÇIK, MIT):** Lokal klon üzerinden gerçek koddan çıkardım — `agent/` (128+ modül), `tools/` (40+ araç), `skills/`, `gateway/`, `providers/`, `cron/`. Her iddia bir dosya/satıra dayanıyor.

**Çıktı:** `claude-code-harness.md` (343 satır: bootstrap → ana döngü → tool envanteri → permission/hooks → sub-agent → context yönetimi → skills/slash/plan mode → çok-yüzeyli tek motor) · `hermes-agent-harness.md` (486 satır: kimlik → katman haritası → tool-call formatı → bootstrap → `run_conversation` → tool yürütme 3 kip → context → learning loop → MAS 4 patern → gateway → cron).

**Neden böyle:** İki belgeyi yan yana yazmak, "kaynak açıklığı"nın belge kalitesini nasıl değiştirdiğini gösterdi. Kapalı kaynakta iddia seviyesini düşürmek ve bunu **okuyucuya söylemek** zorundasın; açık kaynakta her cümleyi satıra bağlayabiliyorsun. İkisini aynı güvenle sunmak sahtekârlık olurdu.

**Günün en kritik içgörüsü (Hermes):** Harness, Hermes modellerinin **eğitildiği trajectory formatını** yayıyor — `agent_runtime_helpers.py` konuşmaları `"from": "gpt"` / `<think>` / `<tool_call>` bloklu training-shaped trajectory'ye çeviriyor. Yani "prompt'a XML gömme" bir tercih değil, **modelin fine-tune edildiği sözleşme**. Model/harness ortak tasarımı — Hermes'i genel bir framework'ten ayıran şey bu.

### 3. MAS + subagent — beş ajanın çok-ajan mekanizması

**Ne:** Codex · OpenCode · Hermes · OpenClaw · Claude Code'un MAS/subagent mekanizmasını *nasıl tetiklenir → süreç nasıl akar → terimler ne demek* düzeyinde karşılaştırma.

**Nasıl:** Önce ortak imzayı buldum — beşi de aynı özü paylaşıyor: **delege et → izole context'te çalıştır → özet/sonuç döndür.** Fark asla bu imzada değil, dört eksende:
1. **Tetikleyici** (model / kullanıcı / sistem)
2. **İzolasyon birimi** (thread / session / process-içi task)
3. **Koordinasyon omurgası** (fonksiyon dönüşü / event kuyruğu / paylaşılan pano / mailbox)
4. **Recursive'e bakış** (child kendi child'ını açabilir mi)

En derin ayrım **iki MAS ailesi**: *özet-dönüşlü delege* (Codex, OpenCode, Claude `Task`, Hermes `delegate_task`) vs *pano/mailbox tabanlı* (Hermes Kanban, Claude agent-teams).

**Çıktı:** `mas-4-agent-karsilastirma.md`, 256 satır, sonunda beşli özet matris. Hermes'in **dört ayrı MAS paterni** ayrı ayrı açıldı: `delegate_task`, async delegation (event kuyruğu), Kanban dispatcher/worker (blackboard), MoA (ensemble).

### 4. Agent nasıl tanımlanır ve spawn edilir — "model şema yazmaz"

**Ne:** Tek bir soruyu beş sistemde tam mekanikle cevaplayan belge: bir subagent oluşurken **model mi şema yazıyor**, yoksa sadece **tool parametrelerini mi dolduruyor**?

**Nasıl:** Cevabı iki katmana ayırdım:

| Katman | Ne | **Kim yazar** | Ne zaman |
|---|---|---|---|
| 1. Deklaratif tanım | ad, tool'lar, model, system prompt | **İnsan** (dosya) *veya* **harness** (üretir) | tasarım zamanı |
| 2. Runtime spawn | "şu agent'ı şu görevle çalıştır" | **Model** (argüman doldurur) | çalışma zamanı |

**Model yalnızca Katman 2'yi yapar — orada bile şema yazmaz, sadece argüman doldurur.** İki spawn yolu var: *Yol A* insan-yazımı tanım + model referans verir, *Yol B* dosyasız, harness parametreden üretir.

Sistem sistem: Claude Code → Markdown + YAML frontmatter (Yol A) · OpenCode → MD-frontmatter veya JSON (Yol A) · Codex → TOML config + roller (A tanım + B spawn) · Hermes → YAML profil ama **çoğunlukla dosyasız** (Yol B) · OpenClaw → config → zod şema (A + hibrit).

**Çıktı:** `agent-tanimlama-ve-spawn.md`, 216 satır, sonunda "agent'ı neyle tanımlıyorsun" karşılaştırma tablosu ve tek cümlelik zihin modeli.

**Neden böyle:** Bu soru sık karıştırılıyor — "ajan kendi ajanını yaratıyor" cümlesi doğru gibi duruyor ama mekanik olarak yanlış. Ayrımı netleştirmek, sonraki günlerde kendi sistemimizi tasarlarken doğru soruyu sormamızı sağladı.

### 5. Tool-trace compaction — Hermes satır satır, sonra dört aday

**Ne:** Yalnızca **tool izini** (tool çağrıları + sonuçları) küçültme mekanizması. Genel konuşma-özetlemesi bilinçli olarak kapsam dışı.

**Nasıl:** Önce Hermes'i çekirdek fonksiyonlara inerek yazdım — `_prune_old_tool_results` ve `prune_tool_results_only` (`context_compressor.py`). Dört pass: **dedup** (byte-identik sonuçları tekilleştir) → **informative summary** (büyük sonucu bilgi taşıyan tek satıra indir) → **argüman kısaltma** (assistant tarafı) → **basınç demotion'ı**. Kritik ayrım: bu **hiç model çağırmaz** — ucuz, hızlı, kalite-riski sıfır. Prune boundary'yi (token bütçesi öncelikli, mesaj sayısı yedek, `_MAX_TAIL_MESSAGE_FLOOR = 8`) ve **prompt-cache sözleşmesini** ayrıca açtım.

Sonra aynı derinliği dört adaya uyguladım ve önce **iki felsefeyi** ayırdım:
- **Deterministik per-tool budama** (LLM'siz): Hermes, OpenCode, Codex-truncation
- **LLM-chunk özetleme** (modele sor): OpenClaw, Codex-history, Claude Code

Çoğu sistem ikisini birden kullanıyor: önce ucuz deterministik budama, dolmaya devam ederse LLM özeti.

**Çıktı:** `hermes-tool-trace-compaction.md` (313 satır, uçtan uca önce→sonra örneği + guard/sabit tablosu) · `tool-trace-compaction-diger-adaylar.md` (228 satır: OpenClaw worker-thread'de planlanan chunk özetleme, OpenCode iki katman, Codex ortadan-kesme, Claude Code auto+microcompaction, sonunda beşli mercek tablosu). Her ikisinde de **"POC eşlemesi"** bölümü: hangi fikrimiz kimde var.

**Neden böyle:** Kapsamı daraltmak (yalnızca tool izi) belgeyi kullanışlı kıldı — genel compaction'la karıştırılınca hiçbir sistem karşılaştırılabilir olmuyor. Ayrıca "POC eşlemesi" bölümleri sayesinde bu belgeler ertesi gün (08-06'da) 13 stratejiyi yazarken **doğrudan uygulama kaynağı** oldu.

## Öğrendiklerim

**1. Kaynak açıklığı, belgenin iddia seviyesini belirler.** Claude Code'un reposunda çekirdek kod yok; harness'ı docs + Agent SDK + gözlemlenen davranıştan yeniden inşa etmek gerekti. Hermes'te her cümleyi satıra bağlayabildim. İkisini aynı güvenle sunmak yanlış olurdu — bu yüzden her belgeye kaynak-dürüstlük notu koydum.

**2. Model/harness ortak tasarımı ayrı bir kategori.** Hermes'in XML tool-call formatı bir "tercih" değil, modelin fine-tune edildiği sözleşme. Genel framework'lerde (LangGraph, CrewAI) böyle bir bağ yok. Bu, "hangi harness daha iyi" sorusunun aslında "hangi model için" sorusu olduğunu gösteriyor.

**3. Ortak imzayı bulmak, farkı görünür kılar.** Beş MAS sisteminin hepsi "delege et → izole çalıştır → özet döndür" yapıyor. İmzayı sabitleyince gerçek farklar (tetikleyici, izolasyon birimi, koordinasyon omurgası, recursion) net ayrıldı. Önce ortaklığı bulmadan karşılaştırma yapmak, terminoloji farkını mimari farkı sanmaya yol açıyor.

**4. "Model kendi ajanını yaratıyor" yanlış bir cümle.** Model asla şema yazmaz — yalnızca bir tool çağrısının JSON argümanlarını doldurur. Şema ya insan tarafından bir dosyada yazılır ya harness tarafından parametrelerden üretilir. Bu ayrım küçük görünüyor ama sistem tasarımında her şeyi değiştiriyor.

**5. Kapsamı daraltmak belgeyi kullanışlı yapar.** "Tool-trace compaction" ile "genel context compaction"ı ayırmak, beş sistemi karşılaştırılabilir kıldı. Karıştırılsaydı her sistem "bir şekilde özetliyor" diye tek satıra düşerdi.

**Ders:** Bir repoyu **içeriğine bakmadan** metadata'dan (branch adı, repo adı) yargılama. Ve bir hatayı düzeltirken sessizce silme — düzeltme kaydını bırak, çünkü o hata belgeye dayanarak karar verecek insanı da yanıltmıştı.

**Sorun 2 — Atlas eski bilgiyi taşıyordu (Codex).** Atlas Codex'i "tek ajan" diye kaydetmişti; oysa `spawn_agent` + `multi_agent_v2` + collaboration namespace var. MAS belgesini yazarken kaynağa inince fark ettim ve düzelttim.
**Ders:** Türetilmiş belge (atlas) ile birincil kaynak (kod) çeliştiğinde kod kazanır — ve türetilmiş belgeyi geri güncellemek gerekir, yoksa iki belge birbiriyle çelişir hâlde kalır.
