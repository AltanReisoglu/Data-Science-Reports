00

Özet — üç eksen

OpenClaw bir "chatbot sarmalayıcısı" değil, AI için bir işletim sistemidir. Zeka modelden gelir; oturum, bellek, araç sandbox'ı, erişim kontrolü ve yönlendirme senin altyapında kalır.

Gateway

Kontrol düzlemi + taşıma. Tek WebSocket sunucusu; tüm kanallar, istemciler ve node'lar buraya bağlanır. Host başına tek.

Agent Runtime

Yürütme çekirdeği. Mesaj → bağlam → model çıkarımı → araç yürütme → akış → kalıcılık döngüsü.

Plugin / Capability

Genişletme. Kanallar, model sağlayıcıları, araçlar, bellek ve bağlam motorları hep yetenek sözleşmeleri üzerinden.

Kod: TypeScript, pnpm monorepo. Protokol TypeBox şemalarıyla tanımlanır; JSON Schema ve Swift modelleri bu tek kaynaktan üretilir → baştan sona tip güvenliği.

02

Gateway — kontrol düzlemi

OpenClaw'un tek kontrol düzlemi ve node taşıma katmanı. Her istemci WebSocket ile bağlanır, el sıkışmada bir rol ve kapsam (scope) bildirir. Güncel protokol v4.

El sıkışma (handshake)

  • İlk çerçeve mutlaka connect olmalı; değilse sert kapatma.
  • Gateway bir challenge nonce yollar → istemci connect gönderir (protokol aralığı, rol, scope, caps, imzalı cihaz kimliği) → Gateway hello-ok döner.
  • Her bağlantı nonce'u imzalar; yeni cihaz = pairing onayı gerektirir.
  • Ön-kimlik çerçeveleri 64 KiB ile sınırlı (DoS koruması).

Roller & kapsamlar

  • operator — kontrol düzlemi istemcisi
  • node — yetenek sunucusu (kamera/ekran/canvas/system.run)
  • Scope kapalı kümesi: operator.read / write / admin / approvals / pairing / talk.secrets
  • Hassas metotlar (config.*, update.*) her zaman operator.admin

Dört tasarım ilkesi

Tipli baştan sona

Tüm WS çerçeveleri TypeBox→JSON Schema ile doğrulanır. Bozuk veri el sıkışmada yakalanır.

Event-driven

İstemciler "yeni var mı?" diye sormaz; agent/presence/health/tick olaylarına abone olur.

Idempotency key

Yan etkili işlemler (send, agent) key ister → retry güvenli, dublicate yok.

Fail-closed

Bilinmeyen olay aileleri varsayılan reddedilir. Tanımadığını geçirmez, durdurur.

03

Agent Runtime — yürütme çekirdeği

OpenClaw kendi runtime'ının sahibidir. Döngü oturum başına seri (serialized) çalışır — aynı oturumda iki tur paralel koşmaz.

Agent döngüsü

  • agent RPC doğrular, oturumu çözer, anında {runId} döner (bloke olmaz).
  • Model + thinking/verbose çözülür, skills anlık görüntüsü yüklenir.
  • runEmbeddedAgent çalıştırmayı kuyruklarla serileştirir, akıtır, timeout uygular.
  • Runtime olayları köprülenir: araç→tool, metin→assistant, yaşam döngüsü→lifecycle.

Eşzamanlılık & kilit

Çalıştırmalar oturum-başına "lane" + isteğe bağlı global lane ile serileştirilir (araç/oturum yarışlarını önler). Transcript yazımı ayrıca süreç-farkında dosya kilidiyle korunur (varsayılan 60 sn bekleme).

Hook sistemi — iki katman

HookNe zaman
before_model_resolveProvider/model'i deterministik override etmek için
before_prompt_buildBağlam / sistem promptu enjeksiyonu
before_agent_replyLLM'den önce; turu üstlenip sentetik yanıt dönebilir veya susturabilir
before_tool_call / after_tool_callAraç parametre/sonuçlarını yakalar · {block:true} terminaldir

NO_REPLY sessiz token'ı giden yükten filtrelenir; mesajlaşma aracı dublikeleri kaldırılır.

04

Uçtan Uca Mesaj Akışı

Bir WhatsApp mesajının yolculuğu — tüm bileşenlerin birlikte nasıl çalıştığını gösteren altı faz.

Alım (Ingestion) src/whatsapp/ · Baileys

WhatsApp'tan WS olayı gelir; adaptör metin, medya ve gönderen meta verisini çıkarır.

Erişim kontrolü + yönlendirme access control

Allowlist & DM pairing kontrolü. Geçemezse mesaj burada durur. Geçerse oturum çözülür: operatör→agent:main, DM→…:dm:+…, grup→…:group:…@g.us.

Bağlam kurulumu PiEmbeddedRunner

Oturum diskten yüklenir; AGENTS/SOUL/TOOLS.md okunur, ilgili skill'ler enjekte edilir, memory_search anlamsal benzer geçmişi çeker.

Model çağrısı provider stream

Derlenen bağlam yapılandırılmış sağlayıcıya (Anthropic/OpenAI/Gemini/yerel) token-by-token akıtılır.

Araç yürütme tool loop

Model tool-call isterse runtime araya girer; non-main oturumsa Docker sandbox; tarayıcı istenirse CDP ile Chromium. Sonuç akışa geri beslenir.

Yanıt teslimi persist → JSONL

Parçalar Gateway'den geçer; adaptör markdown'ı dönüştürüp boyut limitine böler, Baileys ile gönderir. Runtime tüm turu transcript'e kalıcılaştırır.

Yaklaşık gecikme (ikincil kaynak, ortam bağımlı): erişim <10 ms · oturum yükleme <50 ms · prompt kurulumu <100 ms · ilk token 200–500 ms · bash <100 ms · tarayıcı 1–3 s.

06

Çok-Agent Yönlendirme

Tek Gateway sürecinde birden çok izole agent koşar — her biri kendi workspace, state dizini ve oturum deposuyla. Gelen mesajlar bindings ile doğru agent'a gider.

Agent

Tam persona kapsamı: workspace dosyaları, auth profilleri, model kaydı, oturum deposu.

Binding

Bir kanal hesabını (Slack workspace, WhatsApp numarası) bir agent'a eşler.

accountId

Kanal hesabı örneği — ör. WhatsApp personal vs biz.

Yönlendirme kuralı — "en spesifik kazanır"

exact peer → parent peer → peer wildcard → guild+roles → guild → team → account → channel → default agent

Aynı kademede çok eşleşme varsa config sırasında ilk gelen kazanır. Match alanları AND semantiğiyle çalışır.

İki kural: agentDir agent'lar arasında asla paylaşılmaz (auth/oturum çakışması). Ajanlar-arası mesajlaşma varsayılan kapalıdır — açıkça etkinleştirilip allowlist'lenmeli.
07

Ajanlar-Arası İletişim (Agent-to-Agent)

Etkinleştirildiğinde bir agent, oturumlar arası koordinasyon için session araçlarını kullanır. Böylece karmaşık işler bölünür, bir agent diğerine iş devreder — sen kopyala-yapıştır yapmadan.

sessions_list

Aktif oturumları/subagent'ları keşfeder — hangi agent müsait?

sessions_send

Başka bir oturuma mesaj yollar. ANNOUNCE_SKIP ile kullanıcıyı rahatsız etmeden sessiz iş devri.

sessions_history

Başka bir oturumun transcript'ini çeker — bağlam paylaşımı, karar için geçmiş.

sessions_spawn / sessions_yield

Programatik yeni izole oturum/subagent yaratır; yield ile tamamlanmayı bekler.

Örnek akış — orkestratör & alt-agent

Orkestratör
Karmaşık görevi parçalara böler → sessions_spawn ile araştırma alt-agent'ı yaratır (izole oturum, ayrı workspace/model olabilir).
Alt-agent
Kendi bağlamında çalışır: araçları kullanır, web'i tarar, sonucu üretir. Orkestratörün transcript'ini görmez (izole).
Orkestratör
sessions_yield ile bekler; alt-agent bitince tamamlanma olayı gelir.
Alt-agent
sessions_send (opsiyonel ANNOUNCE_SKIP) ile sonucu orkestratöre iletir — kullanıcıya çift bildirim gitmez.
Orkestratör
Sonuçları birleştirir, gerekirse sessions_history ile ek bağlam çeker, nihai yanıtı kullanıcıya döner.
Orkestratör (main / üst oturum) Alt-agent (izole subagent)
Güvenlik altı çizili: her subagent izole oturumdur (kendi güven sınırı). İletişim varsayılan kapalı; açıkken de yalnızca allowlist'lenmiş hedeflere. Bu, "bir agent ele geçirilse bile blast radius sınırlı" ilkesini korur.
08

Bağlam Motoru & Compaction

Her model çağrısında "hangi mesajlar, nasıl özetlenir, subagent sınırları nasıl yönetilir" sorusunu yanıtlayan katman. Varsayılan legacy; plugin'lerle değiştirilebilir.

Ingest  →  Assemble  →  Compact  →  After turn
mesaj eklenince · her çalıştırma öncesi (token bütçesi) · pencere dolunca · tur sonrası

Compaction incelikleri

  • Eski turlar özetlenir (kalıcı), güncel mesajlar korunur.
  • Araç çağrıları eşleşen sonuçlarıyla birlikte tutulur; bölme araç bloğuna düşerse sınır kaydırılır.
  • Overflow hatası dönünce compact + retry (düzinelerce sağlayıcının hata dizesi tanınır).
  • Memory flush: compaction öncesi önemli notları diske yazan sessiz tur.

Dayanıklılık & ayrım

  • Plugin motoru çökerse OpenClaw onu karantinaya alıp legacy'ye düşer — agent susmaz.
  • Compaction ≠ Pruning: compaction sohbeti kalıcı özetler; pruning yalnızca eski araç sonuçlarını istek-başına bellekte kırpar.
  • ownsCompaction:true → motor kendi compaction'ını yönetir.
09

Bellek

OpenClaw hatırlamayı düz Markdown dosyalarıyla yapar — gizli/opak durum yok, her şey okunabilir ve düzenlenebilir.

MEMORY.md

Uzun vadeli küratörlü bellek. Oturum başında yüklenir — yalnızca özel/main oturumlarda, grup sohbetine sızmaz.

memory/YYYY-MM-DD.md

Günlük ham notlar. memory_search için indekslenir; her turda prompt'a enjekte edilmez.

DREAMS.md

Opsiyonel — arka plan konsolidasyonu / "dreaming" özeti.

Araçlar

memory_search (hibrit: vektör benzerliği + BM25 anahtar kelime) · memory_get (belirli dosya/satır). Aktif bellek plugin'i sağlar (varsayılan memory-core).

Backend & embedding

SQLite (varsayılan) · QMD · Honcho · LanceDB. Embedding varsayılanı OpenAI; Gemini/Voyage/Mistral/Ollama seçilebilir. Dreaming: sinyalleri puanlar, eşiği geçeni MEMORY.md'ye terfi ettirir.

10

Plugin / Capability Sistemi

Genişletmenin kalbi yetenek (capability) modelidir. Kilit ayrım: plugin bir sahiplik sınırıdır, capability bir çekirdek sözleşmedir.

plugin = sahiplik sınırı

Bir vendor'ın/özelliğin tüm yüzeyi tek plugin'de toplanır.

capability = çekirdek sözleşme

Birden çok plugin uygular veya tüketir. Yeni alan eklerken soru "kim hardcode etsin?" değil, "çekirdek yetenek sözleşmesi nedir?"

Yetenek türleri (seçme)

text inferenceembeddingsspeech / realtime voice transcriptionmedia understandingimage / music / video gen web fetch / searchchannelgateway discovery
⚠ En kritik güvenlik uyarısı: Native plugin'ler Gateway ile aynı süreçte, sandbox'sız çalışır. Kötü niyetli bir native plugin = OpenClaw sürecinde keyfi kod. Bundle'lar (çoğunlukla skills) daha güvenlidir; non-bundle plugin'ler için allowlist + açık yükleme yolları kullan.
11

Node'lar — cihaz yetenekleri

Node'lar aynı WS sunucusuna role: node ile bağlanır ve yetenek iddialarını bildirir. Telefonun agent'ın araç kutusuna dönüşür.

caps

Yüksek seviye kategoriler: camera, canvas, screen, location, voice, talk.

commands

Invoke allowlist'i: camera.snap, canvas.navigate, screen.record, location.get.

permissions

Granüler anahtarlar: camera.capture, screen.record.

Gateway bunları iddia kabul eder ve sunucu tarafı allowlist'lerle zorlar — telefon "yapabilirim" der ama Gateway izin vermezse olmaz. Offline node'lar için dayanıklı iş kuyruğu: node.pending.enqueue/drain.
12

Güvenlik & Sandbox — katmanlı savunma

Güvenlik prompt guardrail'ine değil, üst üste binen hard control'lere dayanır. Sandbox varsayılan kapalı; Gateway süreci her zaman host'ta kalır, yalnızca araç yürütmesi izole edilir.

1Kanal erişim kontrolü — allowlist + DM pairing; mesaj daha agent'a ulaşmadan durur
2Tool policy (allow/deny) — sandbox kurallarından önce uygulanır
3Oturum güven sınırı — main host'ta tam yetkili; dm/group varsayılan sandbox'lı
4Sandbox (Docker) — network:none, readOnlyRoot, capDrop:ALL; tehlikeli bind mount'lar bloklu
5Exec approvals — insan onayı; prepare↔approve arası komut/cwd değişirse reddedilir
6Audit ledger — yalnızca metadata; prompt/mesaj/araç argümanı saklanmaz (30g, 100k kayıt)

Sandbox üç ayarı

Modeoff / non-main / all
Scopeagent / session / shared
Backenddocker / ssh / openshell

Prompt injection savunması

Kullanıcı mesajı, sistem talimatı ve araç sonucu yapısal olarak ayrı tutulur ki saldırgan "araç çıktısını sistem talimatı gibi" enjekte edemesin. Bunlar soft guardrail — asıl zorlama yukarıdaki 6 katmandan gelir. tools.elevated açık bir kaçıştır: iki kapı da (global + per-agent) izin vermeli.
